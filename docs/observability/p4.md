# P4 本地落地与生产准备

用户确认当前仅本地运行、尚未部署上线。本阶段交付隔离验收工具、应用侧开销证据、工作台 SLO 图、报告关联和生产准备模板。生产 HA、同构容量、外部通知与真实成本不标记为已验收。

## 页面与报告

沿用当前工程工作台的四个独立侧栏页面：压测、监控、Trace、日志。监控新增 5m / 6h HTTP 错误预算图及 SLO 边界说明，无流量或 NaN 不填假零。告警规则为 99.9% 初始目标、14.4 倍快窗口 / 6 倍慢窗口，并设短/长窗口最低请求数。规则覆盖持续错误、低流量、无数据、业务 409 和随机未知路由的序列验收。

压测报告增加 `telemetry.json` 和 `k6.log` 下载。快照包含开始/结束 UTC、Git revision、工作树是否有改动、观测源码 SHA256、各后端可用性、实际常驻业务镜像 ID 与采样设置白名单。源码指纹排除 run 结果、虚拟环境和秘密文件；它不是部署镜像内容的证明，镜像 ID 单独记录。已有 RunId 在服务启动与数据重置之前拒绝复用。

k6 从真实响应头保留最多四个 VU 的 Trace ID / Request ID，快照最多保存四组供独立 Trace/日志页定位。网关可能替换客户端 Request ID，所以不拿客户端自造 ID 冒充响应关联。存在 Trace ID 不代表已采样入库，查不到时仍需检查采样、保留与导出故障。关联样本不进入 Prometheus/Loki 索引标签。

`p4-evidence/telemetry.json` 是报告快照功能的独立 smoke 验证，采集时间晚于首轮性能试验，不充当首轮性能试验的起止快照。start 时 Loki ready 临时不可用如实保留；当前工作台 target 状态均正常。历史业务 run 不补造快照或修改为 P4 结果。

## 隔离验收

独立 Compose project 固定为 `seckill-p4`，独立 MySQL/Redis、两个同镜像商品实例和 Collector/Tempo，所有业务目标固定在该项目内，无数据库宿主机端口；不合并到当前业务 Compose，不复用业务库。镜像使用真实商品接口、4 个 Uvicorn 进程、缓存关闭；比较相同 CPU=1 / 内存=384 MiB 的 off/on。

```powershell
docker compose -p seckill-p4 -f performance/config/docker-compose.p4.yml up -d --build database redis tempo collector product-off product-on
.venv/Scripts/python.exe performance/observability/p4_validate.py --label new-trial
.venv/Scripts/python.exe performance/observability/p4_report.py --validation docs/observability/p4-evidence/new-trial-validation.json --output docs/observability/p4-evidence/new-trial-results.md
```

默认每轮 20 秒：进程冷状态 off/on、三组交替 warm off/on、Collector/Tempo 停机期间业务负载、恢复后显式采样新 Trace 查询、100 个随机 404、四进程重启清理聚合计数、隔离数据库停机与恢复。标签不可复用，保留全部失败结果。程序遇到异常保留部分报告，不把缺失阶段算通过。

实测证据：

- [首轮实测](p4-evidence/initial-results.md)：默认全量成功 access log，吞吐损失中位数 6.95%、P95 增幅 0.67%，5% 门禁未通过。
- [成功 access log 采样实测](p4-evidence/budgeted-results.md)：成功且未采样的访问日志抽样 10%，吞吐损失中位数 7.33%、P95 增幅 0.41%，5% 门禁仍未通过。
- [第三轮热点日志收敛实测](p4-evidence/hotpath-results.md)：额外将商品成功数据库读取 INFO 降为 DEBUG；读取计数器、Trace、错误、回退与业务状态日志保留。吞吐损失中位数 **2.23%**，P95 增幅 **-0.08%**，此次本地 5% 开销门禁通过。JSON 为 `p4-evidence/hotpath-validation.json`。

前两轮均无负载 HTTP 错误；Collector/Tempo 停机期间业务正常，恢复后新 Trace 可查。100 个随机 URL 只有一条 `__unmatched__` 404 metric series，重启后旧计数清理。数据库停机返回 503，恢复后返回 200。队列有界且允许丢失，不宣称停机期间全部补传。

这里只测应用侧 metrics/logging/SDK 与 Trace 异步导出的开销。隔离项目没有接入完整 Alloy/Loki/Prometheus 采集；没有完成整套观测平台的容量/成本、磁盘耗尽、Loki 停机或对象存储故障验证。宿主机同时运行其他容器，CPU quota 已接近饱和；20 秒负载不能替代稳态、同构环境、多节点验收。

## 采样与资源预算

共享包升级 0.4.0。`SECKILL_OBSERVABILITY_ENABLED=false` 是基准实验开关，关闭共享 HTTP metrics/access log 与 SDK 初始化，并压低 INFO 日志，保留错误日志、上下文和既有业务计数器。常规运行默认 true，关闭时不应拿缺失 metrics 当健康。

`SECKILL_ACCESS_LOG_SAMPLE_RATIO` 范围 0..1，非法配置拒绝启动，共享包默认 1 保持已有行为。P4 隔离部署与更新后的 observability Compose 模板使用 0.1，可通过环境变量改回 1；所有 HTTP >=400 和已采样 Trace 的关联 access log 全量保留，业务状态/错误日志不受此访问日志采样控制，metrics 全量。商品成功列表/详情 DB 读取改为 DEBUG，计数器仍完整。Compose 的 tracing 开关也支持环境变量覆盖，回滚可只关闭 tracing 而保留 metrics/日志。

Trace 默认 ParentBased 10%，每进程队列 2048 spans、批 256、导出超时 1s。Collector 两消费线程、256 批磁盘队列、重试最多 60s。具体预算、保留与存储估算公式见 [budgets.json](../../performance/config/production/budgets.json)。不保证所有错误均被 head sampling 采集。当前常驻业务容器沿用 P3 镜像和配置；0.4.0 应用代码与采样策略已在独立 P4 镜像验证，没有为性能实验重建现有业务实例。

## 生产准备与门禁

[生产准备目录](../../performance/config/production/README.md) 包含 Collector 两副本 StatefulSet/PVC/PDB/节点反亲和/mTLS/NetworkPolicy 模板、Prometheus/Alertmanager/Tempo/Loki 拓扑约束、保留策略、发布/回滚步骤和验收清单。Collector 配置已用 0.111.0 validate 检查；Kubernetes YAML 已解析，未在实际集群 server-side dry-run。Secret、StorageClass、DNS、对象存储与后端 charts 需要实际环境确认；没有宣称 Tempo/Loki Helm 部署已完成。

`go_live_gate.py` 要求生产环境、七天内 UTC 验收时间、全部检查 true 且证据引用齐全，缺失/本地结果拒绝通过。它是清单门禁，不自动证明人工填写证据的真实性；发布还需审核真实报告。默认示例退出 2 是预期结果。

## 验证

47 项 Python 测试通过，包含关闭遥测仍保留请求上下文、访问日志采样保留错误与已采样 Trace、非法采样参数、关联样本限量、源码指纹排除结果/秘密、快照禁止复写/串 run、报告关联缺失证据、生产门禁缺失/过期/本地拒绝、性能预算回归不可被隐藏。Promtool 的 P2/P3/P4 序列测试全部通过；SLO 六条规则已载入本地 Prometheus。PowerShell 语法检查与 k6 日志 Tee 管道保留失败退出码验证通过；前端 JS 语法检查通过。浏览器确认独立监控页显示八张真实图表及生产未验收说明。

验收后已移除仅用于试验的 seckill-p4 容器、网络与存储，原始 JSON/Markdown 与截图保留。常驻业务和 P3 采集组件仍运行。
