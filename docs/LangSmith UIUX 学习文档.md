## 2. Visual Language：视觉语言服务于判断顺序

### 2.1 视觉层级 [O/I]

截图中的注意力顺序是**当前位置 → 可用操作 → 当前范围 → 数据主题 → 具体图表 → 单点细节**。固定侧栏标示工作域，面包屑标示层级，Monitoring 标题与 Dashboards/Alerts 标示局部模式。右上角蓝色 Dashboard 按钮是该页最强动作；项目、时间、Group by 为上下文控件；Traces 等主题标签把大量图表收束到可扫描的导航层。图表标题、简述、图例、坐标单位依次递减，图线本身才是主证据。[O]

页面大量留白并不代表低信息密度。留白用于区分**导航层**，图表内部的轴、图例和时间点保持密集；Tracing 则把空间优先给宽表，允许大量列同屏并通过过滤器缩小范围。[O/I]

### 2.2 信息密度分配 [O/I]

| 场景 | 密度策略 | 为什么 |
|---|---|---|
| 全局导航 | 稳定、短标签、细分隔线 | 减少跨域定位成本。 |
| 页面头部 | 面包屑、标题、tabs、少数主操作 | 先确认对象与模式。 |
| 监控总览 | 两列大图，图内有标题/解释/图例/单位 | 允许同一时间窗横向比较吞吐、时延、错误。 |
| 追踪列表 | 紧凑宽表、可隐藏列、分面过滤 | 调查异常需要同时比较很多实例属性。 |
| 单实例详情 | 树形结构与折叠字段 | 深信息只在已选择实例后出现。 |
| 空态 | 空间较松、解释性文案和下一步 | 减少新用户不知道从何开始的成本。 |

### 2.3 颜色与排版的语义 [O]

白色主面、冷灰分隔、深海军蓝正文、蓝色选中与主操作构成稳定背景。成功/错误是绿/红，图表序列另有蓝/橙等区分。例如 Trace Count 按 Success/Error 区分，Trace Latency 的 P50/P99 用蓝/橙；颜色在不同图表内绑定的是**图例语义**，并非全站“蓝总是好”。数值、单位、聚合方式和时间窗与颜色同时出现。观察到的 CSS 变量包括背景 #FFFFFF、选中 #E5F4FF、正文 #0F172A、主蓝 #006DDD、细边框 #E2E8F0；这些是视觉材料，不是交互设计本身。[O]

## 3. Component System：组件承担业务语义

| Pattern | LangSmith 中表达的业务语义 | 观察或依据 |
|---|---|---|
| 全局侧栏 | 稳定工作域，跨域切换 | Tracing、Monitoring、Datasets & Experiments、Evaluators 等一级入口 [O] |
| 面包屑 + 资源标题 | 当前组织、模块和项目对象 | Personal / Tracing / 项目；Personal / Monitoring [O] |
| 页内 Tabs | 同一对象的不同任务模式 | Monitoring 的 Dashboards/Alerts；项目的 Tracing/Evaluators/Automations [O] |
| 上下文筛选条 | 共同作用于下面整片数据的范围 | 项目、Last 7 days、Group by [O/D] |
| 主题跳转条 | 长仪表盘内的章节索引 | Traces、LLM Calls、Cost & Tokens、Tools、Run Types、Feedback Scores [O] |
| 分面过滤 + 保存视图 | 缩小追踪集合并复用调查口径 | Status/Run Name/Run Type/Metadata、Views、Columns [O] |
| 图表容器 | 一个指标问题及其趋势证据 | 标题、解释、图例、轴单位、扩展按钮 [O] |
| 紧凑宽表 | 多实例扫描、比较与选择 | Tracing 表含时间、时延、错误、输入输出、成本、反馈 [O] |
| 右侧 peek | 保持列表上下文，同时调查单实例 | trace 树 + Feedback/Input/Output/Attributes；URL 记录所选 trace [O] |
| 配置表单 + 预览 | 让规则影响在提交前可见 | 创建告警左侧阈值/通知，右侧图表预览 [O] |
| 模板库/上手空态 | 帮助首次创建复杂资源 | Eval 模板按主题分类；数据集/实验空态给下一步 [O] |
| 对比矩阵 | 识别基线相对的改善与回退 | 多实验选择、Compact/Full/Diff、回退筛选 [D] |

关键点：组件选择取决于用户要做的判断。聚合用图、实例扫描用表、单实例解释用树和详情、创建规则用表单加预览、差异诊断用对比矩阵。[I]

## 4. Information Architecture：信息如何组织

LangSmith 的结构可抽象为五层：[O/I]

1. **工作区**：组织/应用选择与全局搜索。
2. **工作域**：Tracing、Monitoring、Datasets & Experiments、Evaluators 等。
3. **资源**：项目、仪表盘、告警、数据集、评估器。
4. **资源内视角**：项目的 Tracing/Evaluators/Automations；Monitoring 的 Dashboards/Alerts。
5. **具体实例**：trace、图表数据点、实验样本等。

Monitoring 截图尤其说明**同一屏并非所有信息都直接平铺**：一级侧栏给工作域，页内 tabs 给模式，项目/时间给范围，主题条给章节，图表网格给指标，悬停提示给单点。层级越深，信息越具体。[O/I]

Tracing 是另一种排列：项目先确定调查对象，时间与分面过滤缩小集合，Threads/Traces/Runs 切换观察粒度，表格定位具体 run，再用 peek 查看树和字段。[O] 两种排列共用“先上下文，再聚合/集合，最后实例”的逻辑。[I]

## 5. Page Composition：每种页面有不同框架

### Monitoring 仪表盘 [O]

- 左侧持久侧栏。
- 顶部面包屑。
- 标题 + Dashboards/Alerts + 创建动作。
- 项目与时间范围控件。
- 指标主题索引 + Group by。
- 两列图表网格；每张图有标题、短描述、图例、轴和扩展。
- 图上悬停给时间桶与序列值；截图中的无样本时间桶显示 “No runs”，而不是把无数据解释为 0。
- 图表缺失时出现 “No charting data found”。

### Tracing 项目 [O]

- 面包屑与项目标题、项目操作。
- 项目内 tabs。
- 搜索范围、过滤器、时间、粒度切换、视图/格式/列设置。
- 可横向扩展的数据表。
- 行选中后在右侧打开 trace peek，保留表格上下文。

### Eval [O/D]

- 无数据时先给“创建数据集/运行实验”或评估器模板，不展示空的复杂表格。[O]
- 有实验时，官方文档描述从数据集进入实验列表，多选后 Compare；比较页再切 Compact/Full/Diff，最后进入单样本详情。[D]

## 6. Interaction Model：逐层缩小或放大

1. **范围先于数据**：项目、时间和分组设置在图表上方，改变后作用范围应可见。[O/I]
2. **先扫后查**：看趋势、扫表、选行、展开详情；用户可以在更详细的层级继续回到原集合。[O/I]
3. **展开保留上下文**：trace peek 不迫使用户丢掉表格；图表提供扩展操作；复杂设置用侧面板或弹窗。[O]
4. **调查口径可复用**：Tracing 有 Views、Save View、Columns；实验比较有列过滤和密度切换。[O/D]
5. **对比以基线为中心**：实验的源实验可调整，改善/回退以反馈指标方向判断；不是简单按数值大小给红绿。[D]
6. **跨域有明确入口**：项目页可进 Dashboard/Alerts、Evaluators；trace 可加入 Dataset/Annotation Queue。[O]

## 7. State Design：数据状态是产品语言的一部分

| 状态 | 观察 | 设计含义 |
|---|---|---|
| 有数据 | 图表线、图例、数轴和悬停值；表格有多列实例 | 说明当前范围与指标口径。 |
| 时间桶无样本 | 悬停提示显示 No runs [O] | 保留“无样本”和真实 0 的区别。 |
| 整张图无数据 | No charting data found [O] | 不绘制伪造的零线。 |
| 资源为空 | 数据集、评估器和队列页显示创建或引导入口 [O] | 给出下一步，而非只有空白。 |
| 实例异常 | Tracing 可按 error/status 过滤 [O] | 错误是查询维度，也是详情线索。 |
| 创建未满足条件 | 数据集名称为空时创建按钮不可用 [O] | 在提交前阻止无效状态。 |
| 比较中出现回退 | 红/绿、计数与筛选配合 [D] | 状态既可扫描，也可进入原因分析。 |

加载、采集延迟、权限、离线和部分失败等细节未在本次页面逐一实测，不能宣称 LangSmith 如何处理；目标产品必须自行定义这些状态。[I]

## 8. User Flow：从任务到证据的路径

### 发现异常 [O/I]

Monitoring 选择项目与时间 → 看 Traces 的数量、时延和错误趋势 → 用同一时间窗定位异常区间 → 进入 Tracing 项目 → 过滤状态/名称/元数据 → 选择 trace → 在 peek 中看树、输入输出和属性 → 必要时加入后续标注或数据集。

### 配置监控 [O/D]

Monitoring 进入 Alerts → 创建告警 → 选择项目和指标 → 设过滤、阈值及通知 → 在右侧预览对应时间序列 → 提交。创建仪表盘则先命名和选择范围，再配置图表的数据源、指标、过滤/分组和图形。[O/D]

### 评估回归 [D]

数据集 → 实验列表 → 多选实验 → Compare → 设源实验与反馈方向 → 看回退数/改善数 → 过滤回退样本 → 切 Full 或 Diff → 进入样本详情/并排 trace。

## 9. 对上版秒杀工作台迁移的诊断 [I]

上版主要统一了色值、边框、侧栏和指标摘要；侧栏各项仍跳到同一长页面锚点，配置、历史、报告、可观测、监控、Eval 顺序堆叠。它缺少**资源层级、页面职责、上下文范围、列表到详情、跨域调查路径、状态口径**。因此视觉接近工作台，操作模型却没有形成工作台。Style.md 应以秒杀平台业务对象重新定义这些结构，而不是按 LangSmith 控件名称罗列迁移清单。

## 10. 调查结论与保留问题

可确定的核心方法是：**按对象分层，按任务切视角；范围控制放在数据之前；聚合与实例使用不同组件；深入时保留上层上下文；空/缺失/异常必须有明确语义。**[O/D/I]

仍需实测：已填充的数据集与实验页、人工标注队列的任务分配、深色主题、窄屏追踪表格，以及各类网络失败状态。它们不构成当前 Style.md 的事实依据。
